# Роли и права — кейс 3
## Матрица ролей (заполни)
- Мерчант - заведение, пользующееся услугами сервиса компании.
- Официант - сотрудник мерчанта, получающий чаевые.
- Клиент - посетитель заведение, который оплачивает чаевые.
- Администратор - уполномоченный компании, занимающийся поддержанием работы сервиса, в том числе и подтверждением некоторых действий на платформе.


|Действие | Мерчант | Официант | Клиент | Администратор |
|-|-|-|-|-|
| Регистрация в платформе | да | нет | нет | да |
| Генерация QR на чек | да | нет | нет | нет |
| Просмотр своих чаевых | да | да | нет | да |
| Сканирование QR | нет | нет | да | нет |
| Оплата чаевых | нет | нет | да | нет |
| Просмотр отчёта по заведению | да | нет | нет | да |
| Блокировка мерчанта | нет | нет | нет | да |
| Изменение справочников | да | нет | нет | да |



## Процесс регистрации мерчанта (заполни)
| Шаг | Кто делает | Что происходит | Проверки |
|-|-|-|-|
| 1 | Мерчант | Подаётся заявка по форме в систему, указывая название (`name`) и описание заведения  (`description`)| Проверка содержимого `name`, `description`, отсутствие дубликатов. |
| 2 | Система | В базу данных записывается строка, мерчанту присваивается `merchant_id` и статус `PENDING` для дальнейшей проверки админстратором | Проверка уникальности `merchant_id`; права `PENDING` аналогичны статусу `BLOCKED` |
| 3 | Администратор | Администратор вручную проверяет мерчант, отдавая системе указ об принятии (`ACTIVE`) / отклонении (`BLOCKED`) заявки | Проверка полномочий администратора |
| 4 | Система | Система в зависимости от указа администратора меняет статус мерчанта с `PENDING`на `ACTIVE` / `BLOCKED` в зависимости от решения администратора; фиксация события в журнале аудита.| Проверка указа администратора на соответствие времени и полномочий |


## Процесс регистрации сотрудника (заполни)
1. Официант передаёт своё имя и платёжные данные мерчанту.
2. Мерчант передаёт данные в систему.
3. Система создаёт строку в базе данных `employes.csv`, присваивая сотруднику `employes_id` (формат `e_NNN` где NNN - номер), `merchant_id` (равен `merchants.merchant_id` мерчантера), указывая `name` и сохраняя платёжные данные в `payment_details`, маскируя по маске (****1234).

## Критерий приёмки
* [ ] Все 4 роли описаны
* [ ] Матрица прав заполнена (8 действий × 4 роли)
* [ ] Регистрация мерчанта: 4 шага с проверками
* [ ] Регистрация сотрудника: 3–4 шага
* [ ] Реквизиты сотрудника маскируются (****1234), не хранятся открыто
* [ ] Клиент может сканировать QR только своего чека (привязка к receipt_id)
